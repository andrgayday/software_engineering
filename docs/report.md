# Пояснительная записка

**Проект:** анализ тональности русского текста с готовой нейросетью.

**Автор и исполнитель всех работ:** Гайдай Андрей Юрьевич.

## 1. Введение. Описание задачи

Цель работы — создать приложение с использованием готовой библиотеки машинного
обучения. Приложение принимает короткий русский текст и показывает его тональность:
положительную, нейтральную или отрицательную. Возможный сценарий — первичный анализ
отзыва или сообщения. Пользователь работает через браузер; интеграции могут
использовать HTTP API. Результат является предположением модели.

Задачи проекта: выбрать готовую модель, реализовать ввод и валидацию текста,
подключить локальный инференс, проверить ответы и описать результаты. Собственное
обучение и сравнение нескольких моделей не входят в текущую версию.

## 2. Обзорная часть

Для работы с готовыми моделями выбрана библиотека Hugging Face Transformers.
Она предоставляет согласованные интерфейсы загрузки токенизатора и нейросети.
Вычисления выполняет PyTorch. FastAPI предоставляет HTTP API и автоматически
формирует OpenAPI-контракт; HTML, CSS и JavaScript реализуют пользовательский экран.

Используется модель `cointegrated/rubert-tiny-sentiment-balanced` — компактная
BERT-модель для классификации коротких русских текстов. В отличие от подхода
с простым подсчётом эмоциональных слов, механизм внимания учитывает контекст
токенов. Готовые веса позволяют реализовать приложение без собственного корпуса
для обучения и без обучения большой сети на учебном компьютере.

Источник сведений о назначении, классах и обучении:
[карточка модели](https://huggingface.co/cointegrated/rubert-tiny-sentiment-balanced).

## 3. Постановка задачи машинного обучения

Задача — классификация текста по трём классам. Вход: строка на русском языке.
Выход: одна метка из множества `{negative, neutral, positive}`. Это оценка
тональности всего фрагмента, а не определение каждой эмоции или каждого предложения.

Текст должен содержать от 1 до 5000 символов после удаления пробелов по краям.
Это ограничение интерфейса. Токенизатор дополнительно обрезает текст до лимита
модели, поэтому приложение предназначено для коротких сообщений.

Функциональные требования: ввод текста; отображение класса по-русски; сообщения
об ошибках; API `POST /sentiment`. Нефункциональные требования: локальная работа
на CPU, однократная загрузка модели при старте, воспроизводимая версия весов,
отсутствие сохранения пользовательских текстов.

## 4. Набор данных и подготовка

Собственное обучение не выполнялось: используется модель с опубликованными весами.
Согласно карточке, авторы использовали несколько наборов русскоязычных текстов,
привели данные к трём классам и балансировали источники и классы с помощью
увеличения и уменьшения числа примеров. Среди источников — mokoron, RuReviews,
RuSentiment, LINIS и SentiRuEval. Исходные обучающие данные в проект не загружаются.

Для демонстрационной проверки составлен CSV `evaluation/examples.csv` из 30 фраз:
10 отрицательных, 10 нейтральных и 10 положительных. Метки назначены вручную при
подготовке примеров. Набор небольшой, без независимой экспертной разметки; он
проверяет понятные сценарии, но не представляет распределение реальных отзывов.

При использовании модели сохраняются регистр, знаки препинания и слова исходного
текста; удаляются только пробелы по краям API-запроса. Штатный токенизатор
преобразует текст в идентификаторы токенов и маску внимания, добавляет специальные
токены и выполняет обрезку до допустимого размера. При пакетной проверке применяется
padding. CSV проверяется на непустой текст и допустимые метки. Контрольная сумма
CSV сохраняется в отчёте проверки.

## 5. Архитектура модели и метод обучения

Готовая модель представляет собой RuBERT-tiny, адаптированную автором для
классификации тональности. BERT использует представления токенов и позиции,
блоки Transformer с механизмом самовнимания и классификационную голову.
Модель возвращает три логита; приложение выбирает индекс максимального значения
и переводит его в метку через `model.config.id2label`.

В проекте веса не изменяются: модель работает в режиме `eval()`, а вычисления —
в `torch.inference_mode()`. Оптимизатора, функции потерь, эпох обучения и подбора
гиперпараметров в приложении нет. Метод подготовки весов описан автором в
[разделе Training карточки модели](https://huggingface.co/cointegrated/rubert-tiny-sentiment-balanced#training).
Нельзя приписывать приложению опубликованные автором результаты как свои.

Версия весов закреплена revision `e0679dd4460e48648f5d4d819ae0f505384f5a9d`.
Токенизатор и веса загружаются из одной версии. После загрузки параметры копируются
в отдельную память: это сохранённый обход наблюдавшегося сбоя mmap/safetensors
на данном Mac. Пользовательские тексты в Hugging Face для инференса не отправляются.

## 6. Оценка качества и графики

Проверка реальной модели выполняется командой:

```bash
uv run python -m evaluation.run
uv run python -m evaluation.plots
```

Результаты сохранённого запуска на 30 демонстрационных фразах:

| Показатель | Значение |
| --- | --- |
| Верных ответов | 28 из 30 |
| Accuracy | 0,9333 |
| Macro-F1 по трём классам | 0,9312 |

Accuracy — доля верных ответов. Для каждого класса F1 = 2TP / (2TP + FP + FN),
macro-F1 — среднее F1 трёх классов. При нулевом знаменателе F1 принимается равным 0.
Матрица ошибок: строки — фактические классы, столбцы — предсказания.

| Фактический / предсказанный | negative | neutral | positive |
| --- | ---: | ---: | ---: |
| negative | 8 | 1 | 1 |
| neutral | 0 | 10 | 0 |
| positive | 0 | 0 | 10 |

![Метрики и матрица ошибок](figures/quality.svg)

Полные фразы, метки и ответы находятся в
[отчёте](../artifacts/pretrained.metrics.json). Результат относится только к
небольшому составленному вручную набору. Он не подтверждает аналогичное качество
на произвольных текстах. Для дальнейшей оценки нужен отдельный, более крупный
корпус реальных сообщений с независимой разметкой, включая отрицания, сарказм
и смешанные эмоции.

Графики обучения отсутствуют, поскольку обучение в проекте не проводилось.
Выполнена оценка готовых весов. Автоматические тесты проверяют HTTP-контракт,
валидацию и расчёт метрик; их успешность не является оценкой качества нейросети.

## 7. Заключение

Реализовано приложение анализа тональности с готовой моделью: пользователь вводит
текст в браузере, получает один из трёх классов и может обращаться к HTTP API.
Код разделён на конфигурацию, жизненный цикл приложения, схемы, маршруты,
инференс, интерфейс и оценку качества. Добавлены воспроизводимая проверка,
JSON-отчёт, график и инструкции запуска.

На демонстрационном наборе получено 28 правильных ответов из 30. Ограничения:
малый объём проверки, отсутствие независимой разметки, обрезка длинных текстов
и возможные ошибки на сложных формулировках. Используется одна модель, поэтому
сравнение нескольких моделей не проводится. Дальнейшая работа — сбор отдельного
размеченного теста, анализ ошибок и проверка на целевой предметной области.
